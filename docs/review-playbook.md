# Essay Studio review map

Read [Review and release](../skills/write-innovation-essays/references/review-and-release.md) for the complete procedure, score calibration and release checks.

## Review the actual result

Define the requested task and constraints, produce a complete first attempt, then review the actual artifact against the current guidebook, author instructions and relevant reference material. Use independent agents when available and appropriate. If independence is unavailable, use distinct review passes and say so honestly.

Useful roles are a skeptical judge, voice/reader editor, evidence reviewer, quantitative reviewer, operations/domain skeptic and design reviewer. Give each a bounded question and the raw artifacts needed. A role title alone does not establish independent review or subject-matter certification.

## Score and repair

Score task fulfillment, correctness, completeness, clarity/usability and presentation/execution from 0–10 with observable reasons. Adapt scope and mark genuinely inapplicable items. A 5 needs substantial revision, 7 is usable with clear weaknesses, 8.5 is strong with minor issues and 9 requires exceptional supporting evidence. Do not inflate a score or average away a critical failure.

Fix critical errors and unmet explicit requirements first, then substantive weaknesses, then polish. Recheck affected areas and plausible regressions. Use up to four review-and-revision rounds; stop once every applicable dimension is at least 8.5 and no known critical error or unmet explicit requirement remains. If a material limitation remains at the bound, disclose it precisely outside the submission and deliver the strongest defensible result.

## Verify what can be observed

Check sources, calculations, units, denominator scopes, formulas, actual code behavior where claimed, document settings, internal/external links, QR payload/access and every final rendered page. Inspect image size, table continuations, captions and exact exported content. Keep historical review snapshots separate from final clearance.

Run representative cold-start tests when changing the reusable skill or production tools. Use a new topic and minimal task-local context, without leaking the expected answer or evaluator's suspected fix.

Keep scores, critic exchanges and process chatter out of the audience deliverable unless the user asks. A concise handover should identify requested files and any material remaining owner action or verification gap. Do not promise a judging result, automatic memory, current funding or operational authorization from a strong essay review.
