# Essay Studio workflow

Start with the repository's entry instructions and the skill at `skills/write-innovation-essays/SKILL.md`. This map is for navigating the detailed working references; it does not replace the full supplied V5 manual or the current competition guidebook.

## Choose the requested mode

Discuss, outline, draft, produce, revise or review according to the user's actual request. Read all current project documents completely before substantive work. A request for a plan does not authorize an unrequested full submission; an authorized production request should continue to a concrete reviewed result.

## Project-specific rules remain project-specific

Load the current guidebook and selected references fully, then adapt the architecture, formatting, page budget and exhibits. JejakBalik is a worked case, not a universal five-page template. Its market, dates, numbers, participants, prototype QR and approved appendix-table size must not leak into another project.

## Completion

The core essay should explain the proposal with appendices closed. The supporting dossier should make its evidence/calculation/operation inspectable. A produced document is complete only after the checks appropriate to its actual format have occurred. Keep unresolved owner actions and precise verification limits outside the audience file.
